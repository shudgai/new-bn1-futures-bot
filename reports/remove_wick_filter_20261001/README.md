# Remove wick-based entry rejection

The user explicitly requested removal of the previous no-entry-on-shadows setting. The current shared contract no longer had the old standalone long-wick helper, but its 35% body/range requirement and 25% doji/range check still rejected signals solely because their wicks grew. Removed both range-based conditions. Three closed directional, nonzero bodies remain required by the current policy; zero-body or opposite-direction candles do not become valid signals. Existing outer-rail confirmation, 0.10 ATR chase limit, market-data validation, account checks and same-candle reentry restrictions remain.

The compatibility state-machine entry also drops its body/range test while retaining its independent 0.30 ATR absolute-body requirement. Held-position exit branches were not changed. Active scanning, engine and account revalidation continue to use the shared contract. No unrelated legacy strategies were enabled or altered.

Verification: 46 tests passed across tests/test_entry_without_wick_filter.py and tests/test_entry_latest_close_runtime.py. The initial 40 shadow/guard tests reproduced 22 failures before the fix, with 18 already passing. Coverage includes both sides, upper/lower/both long wicks on each closed signal candle and the live candle, scanner execution, fresh account/exchange revalidation, zero bodies, opposite colors, missing rail confirmation, malformed OHLC, chase rejection, same-candle cooldown, and the compatibility absolute-body threshold. Exchange calls were mocked; tests sent no real orders. Python compilation and scoped git diff --check passed. Prior unrelated exit-suite failures and missing specifications remain as documented in the preceding entry diagnosis; no whole-repository pass is claimed.

The previous latest_close runtime fix is preserved. Existing report/web working-tree changes were not authored by this task. No commit or push was performed. Deployment verification is in deployment.json.
