# 兩版本比較與流程優化

比較：entry-containment-v2 / 8be7707 與新版 / 52579bd。8006 的程序仍未重啟套用這兩次新修正；本次沒有切換歷史分支。

| 項目 | 舊版 8be7707 | 新版與本次優化 |
| --- | --- | --- |
| 持倉出口 | 含 ATR 回吐階梯及硬止損路徑 | Channel Swing 採價格峰谷與結構破壞；保留 52579bd 的成熟行情即時反向實體出口，不恢復舊 ATR 階梯／硬止損 |
| 谷底反彈 | 不能直接以舊版取代最新出場需求 | 已走出兩根持倉後順向實體、新低形成後，當前反彈實體達前根實體一半且越過前收，即可盤中出場；普通小反彈不平倉 |
| 持倉時開倉觀察 | 沒有新版 CAP／WAIT 觀察流程 | 原本持倉也跑開倉觀察；優化為只有空手時才跑，避免觀察與儲存阻擋持倉出口 |
| 分階段風控 | 已修復明確啟用旗標的專用分流 | 補回新版缺失的分流，支援持倉／metadata 旗標；缺 runtime 明確拒絕落回舊出口，一般持倉不自動啟用 |
| 即時入口標記 | KC_LIVE_BODY_BREAKOUT | 出口同時識別 KC_LIVE_BODY_BREAKOUT／KC_LIVE_CROSS，不因別名清除合法待平 |
| 開倉取樣 | 兩次 REST 讀取間刻意等待 1 秒 | 改為 0.2 秒，省去 0.8 秒刻意等待；仍檢查兩次已收線 OHLC 一致、伺服器時間、3 秒結算及快取 TTL |

沒有改動開倉方向條件、槓桿、資金配置或既有盤整攔截；沒有以放寬報價／收線重驗來提高速度。這是流程優化，不宣稱實際總成交延遲減少 0.8 秒。

## 驗證
