# Direct position reversal

- Date: 2026-10-07 (UTC+8)
- Author: shudgai999 / Codex
- Owner authorization: Replace close-then-revalidate-then-open with a single reversal operation when the opposite direction meets the current complete entry conditions. Preserve 2ATR arming and existing risk exits.
- Implementation: Paper trading commits both accounting legs and the new same-quantity position together without calling ordinary close/open functions or publishing an intermediate FLAT state. Testnet uses one opposite MARKET order of twice the held quantity in verified One-way mode (positionSide=BOTH, reduceOnly=false). This is our netting implementation; Binance's Reverse UI documentation does not establish its internal order count. Hedge mode is rejected without changing the account mode or closing the old position.
- Entry/risk authority: Fresh entry finality, full common contract, price safety, original position identity, current candle, account halts, executable fee/slippage budget and fixed structural risk sizing remain required. A durable position-bound token authorizes held-position evaluation through the existing account firewall and final create_order wrapper. Quantity, client ID, proof, and order type are checked before committing exposure. Matching the opposite signal alone does not grant manual or ordinary-entry bypasses.
- Durability: Persist a unique client order ID before submission. Ambiguous submissions are queried by this ID after restart and candle rollover; never blindly resubmit. Query cooldown limits retry load. Partial terminal fills are recorded at actual executed quantities and block automated top-ups across candle boundaries. Explicit exchange rejection leaves the original position. Late exchange refreshes cannot overwrite a confirmed reversed position; account-level gate halts survive refresh.
- Exits/UI: Qualified structure exits delegate to direct reversal instead of issuing a separate close. Existing verified 2ATR/20-percent giveback, hard stops, and emergency exits retain independent authority outside an in-flight transaction. Old pending/peak state is not copied into a reversed position. Chart displays a single reverse direction marker for completed reversals; trade history retains the two accounting legs with one reverse ID and exchange order ID.
