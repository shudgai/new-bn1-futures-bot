ROOT_CAUSE =
1. **2U Ladder 設定 reason：** 第 241 行，當 `net <= locked_net` 時，設定了 `ladder_reason, ladder_trigger = PEAK_REASON, 'TRAILING_2U_LADDER'`。然後在第 257 行 `reason, trigger = ladder_reason, ladder_trigger`。
2. **Waterfall 的判斷位置：** 第 311 行，Waterfall 的判斷被包在 `if not reason:` 之中。
3. **soft_exit_blocked 清空 reason：** 第 323 行起，檢查 `if reason:`，因為 `trigger` 是 `TRAILING_2U_LADDER`（非 `HARD_REASON` 且非 `WATERFALL_DROP`），加上 `trend_status == 'WARNING'`，所以設定 `soft_exit_blocked = True`，接著在第 346 行 `reason, trigger = None, None` 將其清空。
4. **為何被跳過：** 
   - `reason = PEAK_REASON` (2U_LADDER 佔用)
   - `if not reason:` -> 判斷為 False，Waterfall block 被完全跳過 (already skipped)
   - `if reason:` -> 進行 soft_exit 審查
   - TREND_HOLD ('WARNING') blocks -> `soft_exit_blocked = True`
   - `reason = None`
   結果就是：Waterfall 根本沒被 evaluate，且 2U Ladder 也被擋下，最終回傳 `None`。

MINIMAL_FIX = 
因為 `WATERFALL_DROP` 是 Protective exit（極端保護），不應被 Soft exit（如 2U Ladder）的候選狀態所阻擋。
最小修法是放寬 Waterfall 的進入條件，允許它覆蓋 `PEAK_REASON`（或任何 soft exit）。
將第 311 行的 `if not reason:` 改為：
`if not reason or reason == PEAK_REASON:`
或者，將 Waterfall 的檢查移到 `reason = ladder_reason` 賦值之前獨立檢查。這樣當 Waterfall 條件滿足時，會設定為 `ABNORMAL_REASON` 且 `WATERFALL_DROP`，後續就不會被 `soft_exit_blocked` 清除了。
